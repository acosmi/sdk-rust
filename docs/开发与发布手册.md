# acosmi-sdk (crate `acosmi`) 开发与发布手册

> 适用版本: v2.8.0+
> 最后更新: 2026-06-19

## 1. 项目概览

`acosmi-sdk` 是 Acosmi 模型网关、SDK-facing Agent Run Gateway 与 compliance API 的 **Rust** SDK。它端口自 `acosmi-sdk-ts`（TypeScript SDK 自 2026-05-22 起为事实标准主实现），跨语言契约（snake_case wire-format / 符号名对齐 / bug-for-bug 行为）以 TS 实现为基准（见 §5）。

| 项目     | 值 |
| -------- | -- |
| crate 名 | `acosmi-sdk`（包名）；`lib.name = acosmi`（`use acosmi::Client;`） |
| 实现地位 | TS 主实现的 Rust 端口；wire-format 与符号名与 TS 严格对齐 |
| 当前版本 | **2.8.0**（对齐 npm `@acosmi/sdk-ts` 主线 2.8.x） |
| 主消费者 | Rust 侧下游产品（Anthropic 格式优先），保留双格式 `OpenAIAdapter` 等地位 |
| 长期保留 | `OpenAIAdapter`（P0 红线，与 `AnthropicAdapter` 等地位，恒编译） |
| LICENSE  | MIT — Copyright (c) 2026 Acosmi |

## 2. 仓库与发布拓扑

```
SDK 独立公开仓 (public)                        crates.io 公开 crate
acosmi-sdk-rust                              → crates.io/crates/acosmi-sdk
└── github.com/acosmi/sdk-rust                └── tag v* 触发 release workflow
```

本仓为 **vendored 双 commit** 模型：

- 作为父 monorepo 的 vendored 子目录参与开发（父仓 commit）。
- 作为独立公开仓 `github.com/acosmi/sdk-rust` 对外发布（独立 commit + tag）。
- 两侧均需提交（嵌套仓双 commit），但 **crates.io 的发布物只来自独立公开仓**。

**铁律**：

- SDK 是独立发布物，发布用 tag 只在独立公开仓内打。
- 不把外层 monorepo 的 Java / Go / provider 改动带入 SDK commit。
- 公开仓 history 与提交信息只写产品/SDK 语义，不含协作工具或开发过程元数据（不含 `Co-Authored-By` trailer，不引用内部 `docs/jihua/*` 路径）。
- `docs/` 可放公开用户文档；内部 audit、证书材料、provider runbook 不进公开仓。

## 3. 开发环境

- **rustc / cargo ≥ 1.82**（`Cargo.toml` `rust-version = "1.82"` MSRV 公开承诺，不擅自抬高）。
- `cargo clippy`（lint，发布前以 `-D warnings` 强制零告警）。
- `cargo fmt`（rustfmt 统一格式）。
- 推荐 IDE：VSCode + rust-analyzer，或 RustRover。
- TLS 用 rustls（`reqwest` `default-features = false` + `rustls-tls`），无 native-tls / OpenSSL 系统依赖。

## 4. 目录结构

`src/` 按**业务域 module** 组织：每个域一个文件夹（含 `mod.rs` barrel），`core/` 收口运行时基座，`shared/` 收口跨域基础设施 + 跨域共享 DTO。根 `lib.rs` 只 `pub mod` 各域并逐域 `pub use` re-export，对齐 TS `index.ts` 的单一真源。新增业务域时落对应文件夹 + 在 `lib.rs` 登记，规则唯一明确。

## 5. 编码规范

### Rust 风格（硬规则）

| 类别 | 规则 | 例 |
|------|------|----|
| 函数 / 方法 | **snake_case** | `discover`, `get_adapter_for_model`, `refresh_token` |
| 类型 / struct / enum / trait | **PascalCase** | `Client`, `ServerMetadata`, `AnthropicAdapter`, `Adapter` |
| 错误变体 | **PascalCase**（顶层 `enum Error` 的变体） | `Http`, `Business`, `OrderTerminal`, `ModelNotFound` |
| 常量 | **UPPER_SNAKE_CASE** | `VERSION`, `MAX_DOWNLOAD_SIZE`, `THINKING_HIGH`, `DEFAULT_GATEWAY_BASE_URL` |
| 文件名 / module | **snake_case** | `stream_meta.rs`, `agent_runs/`, `chatbridge/` |
| Wire-format 字段 | **snake_case**（serde 结构体字段名 = wire 契约） | `preferred_format`, `created_at`, `max_tokens` |

### 安全 / 错误处理（硬规则）

- ✅ **`#![forbid(unsafe_code)]`** —— crate 根强制，禁一切 `unsafe`。
- ✅ **错误用 `thiserror`** —— 顶层 `enum Error`（`shared/errors.rs`），所有公开方法返回 `Result<T> = std::result::Result<T, Error>`。
- ✅ **serde snake_case wire 字段即契约** —— `#[serde(rename = "...")]` / 默认字段名严格匹配上游 JSON，0 偏移。
- ❌ 不写 `.unwrap()` / `.expect()` 在可恢复路径（库代码用 `?` 传播；仅测试与编译期常量可豁免）。
- ❌ 不在公开 API 暴露 `provider product/user/transaction/seal-provider` 等 provider 选择字段（compliance / chatbridge 安全边界）。

### 跨语言契约印记（Cargo.toml 注释指向的锚 —— 不许改）

`acosmi-sdk` 是 TS 主实现的 Rust 端口，`src/` 布局自由（见 §4 域文件夹），但以下跨语言契约是与上游 TS / 后端 Go / Java 对照的基准，必须保留。`Cargo.toml` 的契约注释直接指向本节。

**① snake_case wire-format 字段名** —— serde 结构体字段名 / `rename` 即 wire 协议契约，与上游 JSON 0 偏移，不可漂移。

**② 符号名跨语言一致** —— 导出的**类型 / trait / 错误名用 PascalCase**，跨语言一致（`AnthropicAdapter` / `ServerMetadata` / `ComplianceClient` 在 TS↔Rust↔Go 同名），是跨语言对照锚点。

**③ bug-for-bug 四条红线**（行为对齐，改了就是破坏契约）：

1. **POST 默认不重试** —— `default_safe_to_retry` 仅 `GET`/`HEAD`/`OPTIONS` 可重试，其余（含 POST/PUT/DELETE）默认 `false`，**计费双扣保护**。
2. **流式不重试防双扣** —— stream 路径强制 `max_attempts = 1`；错误层 `default_retryable` 显式排除 `Error::Stream`（SSE 已部分写出，重试 = 双 token）。
3. **sanitize 对 thinking + redacted_thinking 硬豁免** —— 历史消息清洗时 `thinking` / `redacted_thinking` 块永不被剥离（上游推理上下文连贯性契约）。
4. **401 单次重试防递归** —— 401 时 refresh + replay 只做**一次**（refresh 是 inner loop，不计入 retry attempt），且只对安全查询（GET/stream/download）生效；写操作 401 不自动 refresh + replay（避免重复创建 / 重复计费）。

**④ 金额三阵营**（**严禁写"金额一律 X"**，会与实际类型矛盾）：

- **钱包域 = `f64`** —— `WalletStats.{balance, monthly_consumption, monthly_recharge}` / `Transaction.amount` 上游 Go `wallet.go` 用 float64，wire 是 JSON 数字 → Rust `f64`（唯一浮点金额端点）。
- **finance + 商品化 = `*Fen` = `i64` 整数分** —— finance 域发票/退款/对公转账（`amount_fen` / `tax_amount_fen` / `requested_amount_fen`）一律 `i64` 整数分，无浮点风险。
- **json.Number 类十进制 = `String`** —— 精度敏感的十进制透传金额用 `String`（如 `OrderListItem.discount_rate` = `Option<String>`）。
  - ⚠️ **同名分歧**：`OrderListItem.discount_rate` = `Option<String>` ⊥ `TokenPackage.discount_rate` = `f64`，bug-for-bug **不可统一**（来源不同源）。

### Rust 不可避免的偏移（与 TS 不 1:1）

| 维度 | TS | Rust |
|------|----|------|
| 方法名 | camelCase（`getAdapterForModel`） | **snake_case**（`get_adapter_for_model`）—— Rust 惯例 |
| 错误处理 | 7 个 `instanceof` Error 子类 + `throw` | 顶层 `enum Error` + `match` / `Result<T>`（变体覆盖 7 类 + Rust 传播工具变体 `Json`/`Io`/`Http2`/`Other`） |
| optional | `?: T` / `T \| undefined` | `Option<T>` |
| 上下文取消 | `AbortSignal` | `tokio_util::sync::CancellationToken` |
| 流返回 | `AsyncIterable<StreamEvent>` | `impl Stream<Item = Result<...>>` |
| 锁 | Promise chain (`this.mu`) | `tokio::sync::Mutex` 单航班门 + `AtomicBool` |
| IO | `fs/promises` async | `tokio::fs` async |

> `enum Error` 的变体与 TS 7 个错误子类对齐：`RateLimit`(↔`RateLimitError`) / `Business`(↔`BusinessError`) / `OrderTerminal`(↔`OrderTerminalError`) / `ModelNotFound`(↔`ModelNotFoundError`) / `Stream`(↔`StreamError`) / `AgentRunStream`(↔`AgentRunStreamError`) / `OAuthTokenEndpoint`(↔`OAuthTokenEndpointError`)，外加 Rust `?` 传播用工具变体 `Http` / `Network` / `Json` / `Http2` / `Io` / `Other`。

## 6. 开发流程

### 改源码 → 提交

```bash
cd <acosmi-sdk-rust>

# 改完后必须通过发布前验证（顺序固定）
cargo fmt --all                                  # 格式化（CI 用 --check 校验）
cargo clippy --all-targets -- -D warnings        # 0 告警
cargo test                                       # all pass（lib + 集成）
cargo build                                       # 默认 feature 编译通过

# commit（双 commit：父仓 + 独立公开仓各自提交）
git status --short
git add <files>
git commit -m "fix(sdk-rust): ..."
```

> 也可用项目内置 `/rust-check`（cargo check + clippy + tests）一把跑全验证。

### Commit message 规范

`type(scope): subject` 风格：

- `feat(sdk-rust): ...` 新功能 / 新域
- `fix(sdk-rust): ...` bug fix
- `refactor(sdk-rust): ...` 重构（无功能变化）
- `docs(sdk-rust): ...` 文档
- `test(sdk-rust): ...` 测试
- `release(sdk-rust): vX.Y.Z` 版本发布

公开仓提交信息只写产品/SDK 变更，**不含 `Co-Authored-By` trailer**，不引用内部计划/审计路径。

## 7. 测试

- 框架：Rust 内置 `#[test]` / `#[tokio::test]`（异步用 `tokio` `test-util`）。
- 位置：单元测试随 `src/**/*.rs` 内 `#[cfg(test)] mod tests`；跨域集成测试在 `tests/`。
- 命令：`cargo test`（全跑）/ `cargo test --test p1_core`（单文件）/ `cargo test <name>`（按名过滤）。

**当前 157 测试全绿**：137 lib（`src/` 内单元测试）+ 20 集成（`tests/p1_core.rs` 10 + `tests/p2_auth.rs` 4 + `tests/p5_billing_skills_notifications.rs` 6）。

### 必测 P0 红线（改了就必跑，红即停车回滚）

- **流式不重试** —— stream 路径 `max_attempts=1` + `default_retryable` 排除 `Error::Stream`（双扣保护）。
- **POST 默认不重试** —— `default_safe_to_retry` 仅放行 GET/HEAD/OPTIONS。
- **401 单次防递归** —— refresh + replay 只一次，写操作不 replay。
- **sanitize thinking 豁免** —— `thinking` / `redacted_thinking` 永不被清洗剥离。
- **双 adapter 选路** —— `get_adapter` / `get_adapter_for_model` 按 `preferred_format` 四级路由，`AnthropicAdapter` + `OpenAIAdapter` 等地位。
- **OpenAIStreamConverter** —— OpenAI SSE chunk → 统一 `StreamEvent` 转换（`new_openai_stream_converter`），含工具调用增量拼装。
- **ensure_token 单航班** —— `Client::ensure_token` 在并发下经单航班门串行化 refresh-rotation，避免雪崩 / 重复轮换。

加测试规则：

- 端口自 TS 的测试用例必须保留 bug-for-bug 断言。
- Rust-only 行为测试（如 `CancellationToken` 取消、`Stream` 背压）单独写文件，不混进端口测试。
- 任何新增/变更 namespace 方法必须有 URL 组装测试（用注入的 mock transport 断言 `method + path + query`），`cargo build` / `clippy` 测不出路径错也测不出路径对。

## 8. 构建与 feature 矩阵

- 工具：`cargo build`（dev）/ `cargo build --release`（发布优化）。
- **feature 矩阵**：

| 命令 | 含义 |
|------|------|
| `cargo build` | 默认（`default = ["sanitize"]`），含历史消息清洗子包 |
| `cargo build --no-default-features` | 关 `sanitize`，最小 lib（验证 `#[cfg(feature = "sanitize")]` 门控正确） |
| `cargo build --all-features` | 开 `sanitize` + `desktop-loopback`（桌面 OAuth loopback HTTP server） |

- **feature 清单**：
  - `default = ["sanitize"]`
  - `sanitize` —— 历史消息清洗子包（对齐 npm 子路径 `./sanitize`），默认开以保 lib 完整。
  - `desktop-loopback` —— `authorize()` 的 loopback HTTP server（桌面 OAuth），按需开启。
- 双 adapter（Anthropic + OpenAI）**恒编译，不 feature-gate**（P0 红线）。

> 发布前应跑全三种 feature 组合编译（`cargo build` / `--no-default-features` / `--all-features`），确保 feature 门控无遗漏。

## 9. 发布流程（crates.io）

### 9.1 一次性配置（首次发布前）

#### A. 公开仓 GitHub Repo

```
github.com/acosmi/sdk-rust (public, MIT)
```

由企业账号 `acosmi`（lowercase）持有，HTTPS clone（避免 host key verification 失败）。

#### B. crates.io API token

1. crates.io → Account Settings → API Tokens → New Token。
2. Name：`acosmi-sdk-ci`。
3. Scope：`publish-update`（发布已存在 crate 的新版本）。如首次发布该 crate 名，还需 `publish-new`。
4. 复制 token（仅显示一次）。

**GitHub repo Secret**：

- repo → Settings → Secrets and variables → Actions → New repository secret。
- Name：`CARGO_REGISTRY_TOKEN`。
- Value：上一步 token。

#### C. release Actions workflow

公开仓 `.github/workflows/release.yml` 关键内容（push tag `v*` 触发）：

```yaml
on:
  push:
    tags: ['v*']

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable
      - run: cargo fmt --all --check
      - run: cargo clippy --all-targets -- -D warnings
      - run: cargo test
      - run: cargo build --no-default-features
      - run: cargo build --all-features
      - run: cargo publish
        env:
          CARGO_REGISTRY_TOKEN: ${{ secrets.CARGO_REGISTRY_TOKEN }}
      - uses: softprops/action-gh-release@v2
        with:
          generate_release_notes: true
```

### 9.2 每次发布

```bash
# === Step 1：确认 SDK 独立仓 ===
cd <acosmi-sdk-rust>
git rev-parse --show-toplevel
git remote -v
git status --short

# === Step 2：升版本 + 验证 ===
# 编辑 Cargo.toml：version = "X.Y.Z"（lib.rs VERSION 经 env!("CARGO_PKG_VERSION") 自动跟随；
#   scaffold_tests::version_is_wired 断言会校验，必须同步升）
cargo fmt --all --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build --no-default-features
cargo build --all-features

# === Step 3：审计 + 敏感材料扫描 ===
git diff --stat
# 敏感材料扫描（应全空）：
grep -rn "docs/jihua" . --include='*.rs' --include='*.md' --include='*.toml'   # 内部计划路径
grep -rniE "BEGIN (RSA|EC|OPENSSH|PRIVATE) KEY|\.jks|\.pfx|\.p12" .            # 证书/私钥/keystore
grep -rn "Co-Authored-By" .                                                    # 协作元数据

# === Step 4：dry-run 打包（看实际进 crate 的文件清单）===
cargo publish --dry-run        # 校验编译 + 列出将打包的文件，确认无 secret / 无超大文件

# === Step 5：提交并推送 ===
git add Cargo.toml <sdk files>
git commit -m "release(sdk-rust): vX.Y.Z"
git push

# === Step 6：发布 tag（触发 cargo publish）===
# 只有确认要触发 crates.io / GitHub Release 时才执行：
git tag vX.Y.Z
git push origin vX.Y.Z
# 如手动发布（不经 CI）：cargo publish
```

> `cargo publish` 不可覆盖已发布版本（crates.io 版本不可变 / 不可删，仅可 `cargo yank` 撤回标记）。发布前务必 `--dry-run` 确认无误。

### 9.3 公开仓清洁度检查清单（push 前必看）

- [ ] 提交作者与信息干净，**不含 `Co-Authored-By` trailer**。
- [ ] commit 范围只含 SDK 发布相关文件。
- [ ] 没有 Java / Go / provider 改动混入。
- [ ] **无 `docs/jihua` / 内部 audit / runbook 路径引用**（`grep -rn "docs/jihua"` 应空）。
- [ ] **无证书 / 私钥 / JKS / PFX / P12 / P7 / 口令**。
- [ ] **无真实 provider endpoint / 域名 / raw payload**。
- [ ] `Cargo.toml` `version` 已升；`lib.rs` `VERSION` 经 `env!` 自动跟随、`version_is_wired` 测试已更新。
- [ ] `Cargo.toml` 无 `publish = false`。
- [ ] 不含 `target/`（`.gitignore` 已排除）。
- [ ] `cargo publish --dry-run` 文件清单符合预期（仅 `src/` / `README.md` / `LICENSE` / `Cargo.toml` 等，无 secret）。

## 10. 版本号策略

对齐 npm 主线 **2.8.x**，独立演进（SemVer）：

- **minor**（x.y.0）：新业务方法 / 新域 / 向后兼容的协议扩展（additive）。
- **patch**（x.y.z）：bug fix（含**行为修复** / 红线收敛而无 API 形状变化）、文档、内部 refactor、packaging fix。
- **major**（x.0.0）：wire-format 不兼容变更、公开 API 移除 / 改签名、`TokenStore` trait 变化、MSRV 抬高、后端契约 BREAKING。

> `Cargo.toml` `version` 与 `lib.rs` `VERSION`（`env!("CARGO_PKG_VERSION")`）必须一致；`scaffold_tests::version_is_wired` 断言钉死该值，升版本时同步更新断言。

## 11. 故障排查

### 11.1 cargo publish 失败

| 错误 | 原因 | 排查 |
|------|------|------|
| `crate version X is already uploaded` | 没升 version | 升 `Cargo.toml` `version`（crates.io 版本不可覆盖） |
| `failed to authenticate` / `401` | `CARGO_REGISTRY_TOKEN` 失效或 scope 不足 | 重建 token，确认含 `publish-update`（首发还需 `publish-new`） |
| `manifest has no description / license` | 元数据缺失 | `Cargo.toml` 补 `description` / `license` / `repository` |
| `package size exceeds limit` | 误打包大文件 / `target/` | 检查 `.gitignore` 与 `include`/`exclude`，`--dry-run` 看文件清单 |
| `1 files in the working directory contain changes` | 工作区脏 | 提交或 stash 后再 publish（或 `--allow-dirty`，发布场景不推荐） |

### 11.2 编译 / clippy 失败

- 改了某域 wire-format 类型（`src/models/types.rs` / `src/compliance/**/types.rs`）→ `cargo build` 报全部 caller，逐处修。
- clippy `-D warnings` 红 → 看具体 lint，不要图方便加 `#[allow(...)]` 掩盖；确需豁免要在 PR 说明理由。
- 不要用 `unsafe` 绕过（`#![forbid(unsafe_code)]` 会直接编译失败）。

### 11.3 test 失败

- 双 adapter 选路 / `OpenAIStreamConverter` 红 = **P0 红线破坏，停车回滚**。
- sanitize thinking 豁免红 = 清洗行为漂移（检查 `thinking` / `redacted_thinking` 与 `tool_use_id` 联动）。
- retry 相关红 = 确认是有意契约变更而非回归（POST 不重试 / 流式不重试是硬契约）。
- `version_is_wired` 红 = 升了 `Cargo.toml` 但忘改断言。

### 11.4 公开仓 push 失败

| 错误 | 排查 |
|------|------|
| `Host key verification failed` | remote 从 `git@github.com:` 改 `https://github.com/` |
| `Updates were rejected ... remote contains work` | 先 `git fetch` + `git pull --ff-only`；仅维护者明确需要时才 force push |
| Contributors 显示异常作者 | 检查本地 `git config user.name/user.email`，修正后重新提交 |

## 13. 维护者

- 源码改动：SDK 独立仓维护者（git config 用 SDK 仓专属身份）。
- 公开仓：通过 §9.2 流程提交与发布，不接受无维护者确认的外部发布 PR。
- crates.io：GitHub Actions 自动发布（push tag `v*` 触发；workflow 见 §9.1.C）。
